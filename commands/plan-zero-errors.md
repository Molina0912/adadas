Create a detailed implementation plan following the ZERO ERRORS methodology.

## PLAN STRUCTURE

### 1. PROBLEM ANALYSIS
Document:
- Problem summary (1-2 sentences)
- What needs to be built/fixed
- Why this is needed (business context)

### 2. INPUTS & OUTPUTS
- List all inputs required
- List all expected outputs
- Identify who will use this

### 3. EDGE CASES
Identify potential edge cases:
- Empty inputs
- Null/undefined values
- Boundary conditions
- Invalid data
- Concurrent access

### 4. APPROACH
Describe the solution approach:
- Algorithm/strategy to use
- Data structures needed
- Architecture pattern
- Alternative approaches considered

### 5. COMPLEXITY
- Time complexity O()
- Space complexity O()
- Performance considerations

### 6. TESTS TO IMPLEMENT
List specific test cases:
- Happy path tests
- Edge case tests
- Error case tests

### 7. DEPENDENCIES
- Required packages/libraries
- API endpoints needed
- External services

### 8. SECURITY CONSIDERATIONS
- OWASP concerns
- Input validation
- Authentication/Authorization
- Data protection

### 9. IMPLEMENTATION STEPS
Break down into small, verifiable steps:
1. Step 1 (with verification)
2. Step 2 (with verification)
3. Step N (with verification)

### 10. VERIFICATION PLAN
How will you verify the implementation works?

## OUTPUT FORMAT

Format as structured markdown with clear sections.
Include estimated effort for each step.
Mark any uncertain items with [NEEDS CLARIFICATION].
