# memory-discipline

## regla

**lo aprendido se guarda. lo guardado se respeta.**

## guardar inmediatamente cuando el usuario

- expresa una preferencia ("siempre usa tailwind", "nunca uses default exports")
- rechaza una idea ("no quiero modales", "no agregues animaciones")
- describe un requisito de negocio recurrente
- corrige tu estilo de comunicacion
- pide explicitamente "recuerda esto"

## tipos de memoria

| tipo | ejemplo |
|------|---------|
| design | "primary color #3b82f6, fonts inter + sf pro" |
| constraint | "nunca usar componentes de mui — rechazado por bundle size" |
| preference | "respuestas en español, sin emojis" |
| feature | "iva uk = 20%, gratis envio > 50 eur" |
| reference | "figma: <url>, docs api: <url>" |

## no guardar

- estructura de archivos (se ve en el codebase)
- detalles de implementacion (se ven en el codigo)
- estado temporal de sesion
- cosas obvias del stack

## antes de proponer

```
□ revise memoria de proyecto?
□ revise memoria de usuario?
□ no estoy proponiendo algo ya rechazado?
□ no estoy contradiciendo una preferencia?
```

## cuando borrar

- el usuario cambia de opinion explicitamente
- la regla queda obsoleta por cambio de stack
- detectas duplicado o contradiccion (consolidar)
